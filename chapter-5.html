Chapter 5: Similarity-Based Learning

How to predict by finding the recipes that are most like a new one, using distances and k nearest neighbors.

1. Big idea

To predict the target of a new instance (the query), find the training instances that are most similar to it and copy their targets. Each instance is a point in a feature space with one axis per feature, and similarity is measured with a distance: the smaller the distance, the more alike the instances are. The nearest neighbor algorithm uses the single closest instance, and k nearest neighbors (k-NN) uses a vote or an average of the k closest ones, which makes it less sensitive to noise.

The planner has 8 recipes it has seen before. Each one has a prep time in minutes and calories per serving, whether I cooked it (Cook it?) and the rating I gave it (1 to 5).

3. Step-by-step calculation

Formulas. Here \(a\) and \(b\) are two instances with \(m\) features each.

\[ d_{\mathrm{Euclidean}}(a, b) = \sqrt{\sum_{i=1}^{m} (a_i - b_i)^2} \qquad d_{\mathrm{Manhattan}}(a, b) = \sum_{i=1}^{m} |a_i - b_i| \] \[ d_{\mathrm{Minkowski}}(a, b) = \left( \sum_{i=1}^{m} |a_i - b_i|^p \right)^{1/p} \]

Minkowski with \(p = 1\) is Manhattan and with \(p = 2\) is Euclidean. To put features on the same scale, use range normalization (for the range 0 to 1):

\[ a_i' = \frac{a_i - \min(a_i)}{\max(a_i) - \min(a_i)} \]
  1. Distance to every recipe, without normalizing. The query is \((20, 480)\).

    The nearest recipe is R3 (distance 25.00), which is a No. But look at R3: its calories are the same as the query's, and its prep time is 25 minutes away. A difference of 25 minutes counts as much as a difference of 25 kcal, and calories vary over a much bigger range, so they dominate the distance.
  2. Normalize the features, and the query too. Prep time goes from 10 to 60 minutes and calories from 300 to 750 kcal. \[ 20' = \frac{20 - 10}{60 - 10} = 0.2 \qquad 480' = \frac{480 - 300}{750 - 300} = 0.4 \] The normalized query is \((0.2,\ 0.4)\).

  4. k nearest neighbors with k = 3. The three nearest recipes are R6, R4 and R8, and all three are Yes, so the prediction is Yes. Use an odd k for two classes, so a vote cannot end in a tie.
  5. Weighted k-NN with k = 5. Closer neighbors count more: each neighbor \(j\) votes with weight \(1 / d_j^2\). \[ \mathrm{score}(l) = \sum_{j \in N_k,\ t_j = l} \frac{1}{d_j^2} \]

  6. A numeric target: the rating. For a number, average the targets of the k nearest neighbors. With k = 3 the neighbors R6, R4 and R8 have ratings 4.0, 4.5 and 3.0: \[ \hat{t} = \frac{1}{k} \sum_{j \in N_k} t_j = \frac{4.0 + 4.5 + 3.0}{3} = 3.8333 \] With distance weights \(w_j = 1/d_j^2\) the prediction is \(\hat{t} = \sum_j w_j t_j \big/ \sum_j w_j = 4.0441\).

The algorithm as a diagram.

flowchart TD
  A["New recipe (the query)"] --> B["Normalize its features with the training ranges"]
  B --> C["Compute the distance to every training recipe"]
  C --> D["Sort by distance and keep the k nearest"]
  D --> E{"Type of target?"}
  E -->|Category| F["Majority vote (or weighted vote)"]
  E -->|Number| G["Average (or weighted average)"]
  F --> H["Prediction"]
  G --> H

k-NN is a lazy learner: it does no training and keeps all the instances, so every prediction computes the distance to all of them. A KD tree arranges the data so that only the neighborhood of the query is searched.

Check it with Python. Edit the code and press Run. Try changing the query to (50, 700).

from math import sqrt
from collections import Counter

recipes = [
    ("R1", 15, 300, "Yes", 4.5),
    ("R2", 20, 650, "No", 2.5),
    ("R3", 45, 480, "No", 3.0),
    ("R4", 10, 520, "Yes", 4.5),
    ("R5", 60, 750, "No", 2.0),
    ("R6", 25, 400, "Yes", 4.0),
    ("R7", 35, 600, "No", 3.0),
    ("R8", 30, 350, "Yes", 3.0),
]
query = (20, 480)  # prep time in minutes, calories in kcal

def euclidean(a, b):
    return sqrt(sum((x - y) ** 2 for x, y in zip(a, b)))

def manhattan(a, b):
    return sum(abs(x - y) for x, y in zip(a, b))

lows = (min(r[1] for r in recipes), min(r[2] for r in recipes))
highs = (max(r[1] for r in recipes), max(r[2] for r in recipes))

def normalize(point):
    return tuple((v - lo) / (hi - lo) for v, lo, hi in zip(point, lows, highs))

def ranked(q, normalized=False, dist=euclidean):
    q = normalize(q) if normalized else q
    out = []
    for name, prep, cal, cook, rating in recipes:
        p = normalize((prep, cal)) if normalized else (prep, cal)
        out.append((dist(q, p), name, cook, rating))
    return sorted(out)

def classify(q, k, normalized=True, weighted=False):
    votes = Counter()
    for d, name, cook, rating in ranked(q, normalized)[:k]:
        votes[cook] += 1 / d ** 2 if weighted else 1
    return votes.most_common(1)[0][0], dict(votes)

def predict_rating(q, k, normalized=True, weighted=False):
    nb = ranked(q, normalized)[:k]
    if weighted:
        w = [1 / d ** 2 for d, *_ in nb]
        return sum(wi * r[3] for wi, r in zip(w, nb)) / sum(w)
    return sum(r[3] for r in nb) / k

print("Nearest without normalizing:", ranked(query, normalized=False)[0][1:3])
print("Nearest after normalizing:  ", ranked(query, normalized=True)[0][1:3])
print("3-NN class:", classify(query, 3)[0])
label, votes = classify(query, 5, weighted=True)
print("Weighted 5-NN:", label, {k: round(v, 2) for k, v in votes.items()})
print("Rating, average of 3:", round(predict_rating(query, 3), 4))
print("Rating, weighted:", round(predict_rating(query, 3, weighted=True), 4))

Expected output: nearest without normalizing ('R3', 'No'), after normalizing ('R6', 'Yes'), 3-NN class Yes, weighted 5-NN Yes with scores 53.01 and 13.21, and ratings 3.8333 and 4.0441.

Other measures of similarity: binary features

Distances do not suit features that are only 1 or 0 (for example vegetarian, gluten-free, dairy-free, spicy). Instead, count how the query and another recipe agree:

  • CP (co-presence): both have a 1. CA (co-absence): both have a 0.
  • PA (presence-absence): the query has a 1 and the other has a 0. AP (absence-presence): the query has a 0 and the other has a 1.
\[ \mathrm{RR} = \frac{CP}{CP + CA + PA + AP} \qquad \mathrm{SM} = \frac{CP + CA}{CP + CA + PA + AP} \qquad \mathrm{J} = \frac{CP}{CP + PA + AP} \]

RR is Russel-Rao (only co-presence counts), SM is Sokal-Michener (co-presence and co-absence count) and J is Jaccard (co-absence is ignored). Different indices can rank the recipes differently, so choose the one that fits the question. For example, the query \((1, 0, 1, 0)\) and a recipe \((1, 1, 1, 0)\) have \(CP = 2\), \(CA = 1\), \(PA = 0\) and \(AP = 1\), so \(\mathrm{RR} = 0.5\), \(\mathrm{SM} = 0.75\) and \(\mathrm{J} = 0.6667\).

def binary_similarity(query, other):
    cp = sum(q == 1 and o == 1 for q, o in zip(query, other))  # co-presence
    ca = sum(q == 0 and o == 0 for q, o in zip(query, other))  # co-absence
    pa = sum(q == 1 and o == 0 for q, o in zip(query, other))  # presence-absence
    ap = sum(q == 0 and o == 1 for q, o in zip(query, other))  # absence-presence
    n = cp + ca + pa + ap
    return {
        "CP": cp, "CA": ca, "PA": pa, "AP": ap,
        "Russel-Rao": round(cp / n, 4),
        "Sokal-Michener": round((cp + ca) / n, 4),
        "Jaccard": round(cp / (cp + pa + ap), 4),
    }

# features: vegetarian, gluten-free, dairy-free, spicy
print(binary_similarity((1, 0, 1, 0), (1, 1, 1, 0)))

The normalized query is \((0.8,\ 0.8889)\). The three nearest recipes are R5 (0.2288), R7 (0.3733) and R3 (0.4990), and all are No, so the prediction is No. The rating is the average of 2.0, 3.0 and 3.0, which is \(8/3 = \mathbf{2.6667}\).

Show answer

\(CP = 1\), \(CA = 1\), \(PA = 1\), \(AP = 1\). So \(\mathrm{RR} = 1/4 = \mathbf{0.25}\), \(\mathrm{SM} = 2/4 = \mathbf{0.5}\) and \(\mathrm{J} = 1/3 = \mathbf{0.3333}\).

print(binary_similarity((1, 1, 0, 0), (1, 0, 0, 1)))

5. Likely on the midterm

  • Calculate distances by hand: Euclidean, Manhattan and Minkowski, \(d_{\mathrm{Minkowski}} = \left(\sum_i |a_i - b_i|^p\right)^{1/p}\).
  • Run the nearest neighbor and k-NN algorithm by hand: sort by distance, take the k nearest, vote or average. Use an odd k for two classes.
  • Know weighted k-NN (weight \(1/d^2\)) and how to predict a numeric target (average of the neighbors).
  • Normalize when the features have very different ranges, and normalize the query with the training ranges. It is not needed when the ranges are similar.
  • Know why k-NN is a lazy learner and why a KD tree is used (to avoid computing the distance to every instance).
  • Know the similarity indices for binary features: Russel-Rao, Sokal-Michener and Jaccard. Cosine similarity and Mahalanobis distance are not on the exam.
  • Know that with many features the feature space is mostly empty (curse of dimensionality), so k-NN needs many more instances, and feature selection helps.
