Chapter 6: Probability-Based Learning

How to predict with Bayes' theorem and the naive Bayes model, using the meals the planner skipped.

1. Big idea

Probability-based learning predicts the target level that is most probable given the evidence in the query. Bayes' theorem lets us reverse a conditional probability: from how likely the evidence is when the event happens, we get how likely the event is when we see the evidence. The naive Bayes model makes this practical for many features by assuming that the features are independent of each other once the target level is known. Smoothing then removes the zero probabilities that a small dataset produces.

2. Meal planner example

The planner has a history of 12 planned meals. For each one it recorded the prep time, the day it was planned for, whether I had most of the ingredients at home, and whether I skipped the meal.

3. Step-by-step calculation

Formulas.

\[ P(X \mid Y) = \frac{P(Y \mid X)\,P(X)}{P(Y)} \qquad P(Y) = \sum_i P(Y \mid X_i)\,P(X_i) \]

The second formula is the theorem of total probability. With several features \(q[1], \dots, q[m]\) and a target \(t\), Bayes' theorem gives the posterior of each target level \(l\):

\[ P(t = l \mid q[1], \dots, q[m]) = \frac{P(q[1], \dots, q[m] \mid t = l)\,P(t = l)}{P(q[1], \dots, q[m])} \]

The denominator is the same for every level, so for a prediction we only compare the numerators (this is the maximum a posteriori, or MAP, prediction). The naive Bayes model assumes conditional independence: \(P(X, Y \mid Z) = P(X \mid Z)\,P(Y \mid Z)\). Then:

\[ M(q) = \arg\max_{l \in \mathrm{levels}(t)} \left( \prod_{i=1}^{m} P(q[i] \mid t = l) \right) \times P(t = l) \]
  1. Bayes' theorem by hand (the example from class). A test is 99% accurate and the disease strikes 1 in 10,000 people. We know \(P(d) = 0.0001\), \(P(t \mid d) = 0.99\) and \(P(t \mid \neg d) = 0.01\). The probability of a positive test comes from total probability: \[ P(t) = 0.99 \times 0.0001 + 0.01 \times 0.9999 = 0.010098 \] \[ P(d \mid t) = \frac{P(t \mid d)\,P(d)}{P(t)} = \frac{0.99 \times 0.0001}{0.010098} = 0.0098 \] A positive test means only about a 1% chance of having the disease, because the disease is so rare. This is why Bayes' result can go against intuition. 
    p_d = 0.0001           # P(disease)
p_t_given_d = 0.99     # P(positive | disease)
p_t_given_not_d = 0.01 # P(positive | no disease)

p_t = p_t_given_d * p_d + p_t_given_not_d * (1 - p_d)  # total probability
print("P(t) =", round(p_t, 6))
print("P(d | t) =", round(p_t_given_d * p_d / p_t, 4))
  2. Priors from the meal history. \(P(\text{Skipped} = \text{Yes}) = 5/12 = 0.4167\) and \(P(\text{Skipped} = \text{No}) = 7/12 = 0.5833\).
  3. Conditional probabilities by counting. Within the 5 skipped meals and within the 7 cooked meals, count how often each feature value appears.
    Feature valueGiven Skipped = Yes (5 meals)Given Skipped = No (7 meals)
    Prep time = Short\(1/5 = 0.2000\)\(5/7 = 0.7143\)
    Prep time = Long\(4/5 = 0.8000\)\(2/7 = 0.2857\)
    Day = Weekday\(5/5 = 1.0000\)\(4/7 = 0.5714\)
    Day = Weekend\(0/5 = 0.0000\)\(3/7 = 0.4286\)
    Ingredients at home = Most\(1/5 = 0.2000\)\(5/7 = 0.7143\)
    Ingredients at home = Few\(4/5 = 0.8000\)\(2/7 = 0.2857\)
  4. Score each level for the query (Long, Weekday, Few). Multiply the prior by the conditional probability of each feature value. \[ \text{Yes: } \tfrac{5}{12} \cdot 0.8 \cdot 1.0 \cdot 0.8 = 0.2667 \qquad \text{No: } \tfrac{7}{12} \cdot 0.2857 \cdot 0.5714 \cdot 0.2857 = 0.0272 \] The largest score is Yes, so the planner predicts skipped. If we want a probability, divide by the sum of the scores: \(0.2667 / (0.2667 + 0.0272) = 0.9074\).
  5. The zero problem. Take the query (Long, Weekend, Few). In the history, no skipped meal was on a weekend, so \(P(\text{Weekend} \mid \text{Yes}) = 0\) and the Yes score is \(0.0000\), whatever the other features say. The No score is 0.0204, so the model predicts cooked only because one probability is zero. The dataset is too small to have seen that combination.
  6. Smooth the probabilities. Laplace smoothing adds a small count \(k\) to every level, where \(|\mathrm{Domain}(f)|\) is the number of levels of the feature. Here \(k = 1\) and every feature has 2 levels. Priors are not smoothed. \[ P(f = v \mid t) = \frac{\mathrm{count}(f = v \mid t) + k}{\mathrm{count}(f \mid t) + k \times |\mathrm{Domain}(f)|} \]
    Feature valueSmoothed, given YesSmoothed, given No
    Prep time = Short\((1+1)/(5+1\cdot 2) = 0.2857\)\((5+1)/(7+1\cdot 2) = 0.6667\)
    Prep time = Long\((4+1)/(5+1\cdot 2) = 0.7143\)\((2+1)/(7+1\cdot 2) = 0.3333\)
    Day = Weekday\((5+1)/(5+1\cdot 2) = 0.8571\)\((4+1)/(7+1\cdot 2) = 0.5556\)
    Day = Weekend\((0+1)/(5+1\cdot 2) = 0.1429\)\((3+1)/(7+1\cdot 2) = 0.4444\)
    Ingredients at home = Most\((1+1)/(5+1\cdot 2) = 0.2857\)\((5+1)/(7+1\cdot 2) = 0.6667\)
    Ingredients at home = Few\((4+1)/(5+1\cdot 2) = 0.7143\)\((2+1)/(7+1\cdot 2) = 0.3333\)
    For the query (Long, Weekend, Few): \[ \text{Yes: } \tfrac{5}{12} \cdot 0.7143 \cdot 0.1429 \cdot 0.7143 = 0.0304 \qquad \text{No: } \tfrac{7}{12} \cdot 0.3333 \cdot 0.4444 \cdot 0.3333 = 0.0288 \] Neither score is zero any more, and the prediction changes to skipped: a long meal with few ingredients is more likely to be skipped, even if it was never seen on a weekend.

Check it with Python. Edit the code and press Run. Try k=2 or a different query, such as ("Short", "Weekend", "Few").

from collections import Counter

meals = [
    ("Long", "Weekday", "Few", "Yes"),
    ("Long", "Weekday", "Few", "Yes"),
    ("Long", "Weekday", "Most", "Yes"),
    ("Long", "Weekend", "Most", "No"),
    ("Short", "Weekday", "Most", "No"),
    ("Short", "Weekday", "Few", "No"),
    ("Short", "Weekend", "Most", "No"),
    ("Short", "Weekend", "Few", "No"),
    ("Long", "Weekday", "Most", "No"),
    ("Short", "Weekday", "Few", "Yes"),
    ("Long", "Weekday", "Few", "Yes"),
    ("Short", "Weekday", "Most", "No"),
]  # prep time, day, ingredients at home, skipped?
domains = [("Short", "Long"), ("Weekday", "Weekend"), ("Most", "Few")]

def prior(label):
    return sum(r[-1] == label for r in meals) / len(meals)

def cond(i, value, label, k=0):
    # P(feature i = value | skipped = label), with Laplace smoothing k
    rows = [r for r in meals if r[-1] == label]
    count = sum(r[i] == value for r in rows)
    return (count + k) / (len(rows) + k * len(domains[i]))

def score(query, label, k=0):
    s = prior(label)
    for i, value in enumerate(query):
        s *= cond(i, value, label, k)
    return s

def predict(query, k=0):
    scores = {label: score(query, label, k) for label in ("Yes", "No")}
    return max(scores, key=scores.get), scores

def show(query, k=0):
    label, scores = predict(query, k)
    print(query, "k =", k, "->", label, {l: round(s, 4) for l, s in scores.items()})

show(("Long", "Weekday", "Few"))
show(("Long", "Weekend", "Few"), k=0)
show(("Long", "Weekend", "Few"), k=1)

Expected output: Yes with scores 0.2667 and 0.0272; then No with scores 0.0 and 0.0204 (the zero problem); then Yes with scores 0.0304 and 0.0288 after smoothing with \(k = 1\).

4. Practice exercise

Exercise A. Use Bayes' theorem to compute \(P(\text{Skipped} = \text{Yes} \mid \text{Prep time} = \text{Long})\). Then check it by counting the Long meals.

Show answer

\(P(\text{Long} \mid \text{Yes}) = 4/5 = 0.8\), \(P(\text{Yes}) = 5/12\) and \(P(\text{Long}) = 6/12 = 0.5\).

\[ P(\text{Yes} \mid \text{Long}) = \frac{0.8 \times 5/12}{0.5} = \mathbf{0.6667} \]

By counting: 6 meals have Long prep time and 4 of them were skipped, which is \(4/6 = 0.6667\). Check it:

p_long_given_yes = cond(0, "Long", "Yes")
p_long = sum(r[0] == "Long" for r in meals) / len(meals)
print(round(p_long_given_yes * prior("Yes") / p_long, 4))

Exercise B. For the query (Short, Weekday, Few), compute the naive Bayes scores without smoothing and with \(k = 1\). Does the prediction change?

Show answer

Without smoothing the scores are Yes \(0.0667\) and No \(0.0680\), so the prediction is cooked (by a very small margin). With \(k = 1\) they become Yes \(0.0729\) and No \(0.0720\), so the prediction changes to skipped. When the scores are this close, the smoothing parameter can decide the result.

show(("Short", "Weekday", "Few"), k=0)
show(("Short", "Weekday", "Few"), k=1)

Exercise C. Apply Laplace smoothing with \(k = 3\) to \(P(\text{Weekend} \mid \text{Yes})\) and \(P(\text{Weekend} \mid \text{No})\).

Show answer \[ P(\text{Weekend} \mid \text{Yes}) = \frac{0 + 3}{5 + 3 \times 2} = \mathbf{0.2727} \qquad P(\text{Weekend} \mid \text{No}) = \frac{3 + 3}{7 + 3 \times 2} = \mathbf{0.4615} \]

5. Likely on the midterm

  • Apply Bayes' theorem by hand: \(P(X \mid Y) = \dfrac{P(Y \mid X)\,P(X)}{P(Y)}\), getting \(P(Y)\) from the theorem of total probability when it is not given.
  • Know the product rule \(P(X, Y) = P(X \mid Y)\,P(Y)\), the chain rule for more variables, and the difference between joint, conditional and prior probabilities.
  • Make a MAP prediction: compute the numerator for each target level and pick the largest; the denominator can be dropped.
  • Run naive Bayes by hand: priors, conditional probabilities by counting, multiply, compare. Know that it assumes conditional independence given the target and why that makes it practical (the full joint distribution suffers from the curse of dimensionality).
  • Know why zero probabilities are a problem and how Laplace smoothing fixes them: add \(k\) to the counts and \(k \times |\mathrm{Domain}(f)|\) to the denominator. A larger \(k\) means more smoothing.
  • The rest of the chapter (continuous features with probability density functions, binning, and Bayesian networks) is in sections 6.4.2 to 6.4.4 of the book; read it when the professor covers it.
